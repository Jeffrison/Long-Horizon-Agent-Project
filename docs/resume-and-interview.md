# 简历与面试材料

## 推荐项目名

**Agent 可靠性评测与 LoRA 后训练实验闭环**

可以写的事实：手写 Agent、等调用上限对照、标准答案隔离、可复核单轨迹评测、轨迹监督数据构建，以及实际 0.5B LoRA 训练。不要写旧 README 的准确率提升，不要声称已完成 7B 微调、DPO 或强化学习训练。

## 简历版：Agent 算法方向

- 从零实现 ReAct 工具调用 Agent，集成固定语料 BM25 / Wikipedia 检索与受限 Python 执行，设计结构化工具返回、错误反馈、记忆窗口和统一调用预算，记录逐步输入输出、token 与异常。
- 在冻结的 215 道题上完成 430 条单轨迹成对实验，另对预定 20 题补充两个种子；实现答案隔离、严格 QA/数学判分、逐题 checkpoint、源版本审计与题目聚类置信区间，保留全部错误，禁止重试到正确。
- 分析发现错误反馈主要改善数学协议执行：合法最终答案产出率 51.02%→91.84%，平均调用 6.27→4.37；严格准确率 12.24%→16.33% 的差异区间跨零，不宣称稳定推理增益。

QA 主实验为固定候选语料检索，EM 42.77% / 41.57%，不是官方 HotpotQA 全套指标，也不是原有实时网络条件下的直接前后对比。

## 简历版：后训练方向

- 构建 Agent rollout 到后训练数据的流水线，仅从开发集导出单步 SFT 与相同完整 prompt 的偏好候选，加入去重、来源追溯、按题目分组划分和审核标志，防止同题轨迹跨训练/验证/测试集合。
- 基于 Qwen2.5-7B 教师轨迹构造 78 条 QA SFT 样本，在 8GB GPU 上完成 Qwen2.5-0.5B LoRA SFT（r=16、25 steps）；通过实际 TRL collator 审计屏蔽 45,073 个上下文 token，仅对 completion 计算 loss。
- 在独立开发验证题上比较基座/适配器，token 加权 completion NLL 0.877→0.583；同步建设 215 题严格 Agent 评测与版本化判分，用真实轨迹复核训练与推理效果。

NLL 验证只有 3 道题/15 条样本，属于训练链路验证，不是大规模泛化或准确率提升结论。3 组偏好只作为待审核候选，没有训练 DPO。

## 面试讲述顺序

1. **动机与原型**：自己从底层实现 Agent 执行循环，理解模型输出、工具调用、记忆与终止条件。
2. **评测漏洞**：重复运行直到答对会估计 best-case；标准答案参与提前结束是 oracle leakage；反思 OFF 遇错就失败、ON 可无限格式重试，会混淆预算和策略收益。
3. **修正方法**：推理模块不接收答案，冻结题目/种子/上限；每次尝试计数，答错立即作为该轨迹结果保留；判分独立于模型。
4. **基础设施与实验条件**：实时 Wikipedia 和高并发 API 发生故障，全部存档；新增固定候选语料和明确 API 节流，分别报告实验条件，不能把更容易的检索环境伪装成旧模型提升。
5. **核心发现**：数学格式错误明显减少、调用更少，但正确率区间仍跨零。模型更容易“交出答案”，不等于更会解题；同时看完成、正确、预算和 token 指标。
6. **后训练关联**：保留真实步上下文做单步监督，观察值不作预测目标；偏好必须同 prompt，最终成败是动作质量的噪声标签，需要审核。
7. **验证训练**：实际跑 LoRA，检查 labels=-100 是否正确；按题目隔离验证集，比较基座/适配器的 completion NLL，保存权重哈希。
8. **下一步**：新增未调试数据，做基座/适配器真实 Agent 评测；扩充并审核偏好后再做 DPO，保持独立测试集。

## 要能解释的实现细节

- 每题 × 种子 × 模式只有一条轨迹；三种子结果不选最佳。稳定性小子集直接复用主实验 seed=11 的轨迹。
- “相同预算”指调用/输出上限相同，实际输入输出 token 不同，需要分别报告。
- 同题重复种子相关，主差异按题目聚类 bootstrap；不能把三个种子当作三倍独立新题。
- 数学使用受限 AST 和精确有理数，整数答案严格相等；不从解释文本里抓第一个数。
- Agent 的 status=success 只表示输出了合法最终答案，真正答对由独立 is_correct 判定。
- 源代码、数据与配置都需要冻结；对保存的预测离线重判，不应产生新模型调用。
- 受限 Python 子进程不是恶意代码安全沙箱；本地一次数学演示失败的记录也保留，没有为演示挑选正确样本。

## 不应出现的说法

旧结果“8%→43%”；“完成工业级安全沙箱”；“实现 RLHF/GRPO/DPO 并显著提升”；“达到 HotpotQA 官方榜单水平”；“完全消除网络限流”；“验证集 loss 下降就是答案准确率提升”。

这些边界不是要掩饰的问题，它们是项目设计、实验治理和后续研究计划的一部分。求职材料应围绕已经实现、测量和归档的证据展开。
