# 求职材料草稿（结果数字在正式复测完成后补齐）

## 项目定位

项目名建议：**面向工具调用 Agent 的可靠执行、可复现评测与后训练数据构建**。

当前可以写的能力：手写 ReAct、工具调用协议、错误反馈、预算控制、数据与评测隔离、多种子消融、错误归因、轨迹监督数据构建。项目并未完成 RLHF/GRPO/DPO 训练；可选 LoRA 训练入口不等于已经产出模型权重。

## 简历表述草稿

- 基于 Python 从零实现 ReAct 工具调用 Agent，集成 Wikipedia 检索和受限 Python 执行，设计结构化工具返回、协议错误恢复、上下文窗口与统一推理预算，记录逐步 messages、工具响应和 token 消耗。
- 重构存在答案泄漏和重复采样筛选偏差的历史评测；将推理与 scorer 隔离，设计问题级哈希划分、反思开关等预算对照、三种子成对实验及题目聚类 bootstrap，保留失败与完整轨迹，支持断点恢复和版本审计。
- 构建面向后训练的轨迹数据流水线，仅从开发集导出 SFT 样本与相同完整 prompt 下的偏好候选；实现问题级 train/validation 隔离、数据去重、来源追溯和 completion-only LoRA SFT 入口。

正式复测后，只在实际有统计证据时补充“反思带来 X pp 增益”；若置信区间跨零，就写“完成反思策略消融与错误归因”，不写显著提升。

## 面试讲述

1. **原始动机**：亲手搭建一个小模型可用的工具调用系统，理解不依赖 Agent 框架的执行循环。
2. **发现问题**：多次运行直到正确会估计 best-case，而不是 pass@1；答案参与工具结果提前终止属于 oracle leakage；ON/OFF 有效预算不等导致归因错误。
3. **修正设计**：将标准答案留在 scorer，预声明样本与种子，所有尝试计入分母，并让两组只在错误反馈提示上不同。
4. **不确定性**：同题的三次种子不独立，按题目聚类重采样；实时检索、API 故障、历史数据暴露也影响结论。
5. **后训练关联**：用 rollout 的真实上下文构造单步监督；偏好必须共享同一 prompt，且最终成败只是早期动作质量的噪声标签。
6. **下一步实验**：用新的未调试数据冻结测试集，在单独 GPU 环境完成 LoRA 训练，再进行 base/SFT/审核后 DPO 的同预算评测。

## 不应出现的说法

- “开启反思准确率从 8% 提升到 43%”：旧结果有偏，不能用于求职材料。
- “实现安全沙箱”：当前只是受限子进程，不能安全运行恶意代码。
- “完成 RLHF / GRPO / DPO 并显著提升模型”：没有对应训练与效果证据。
- “达到 HotpotQA 官方榜单水平”：当前不是官方完整评测协议。
- “完全解决限流、工程级/工业级鲁棒性”：需用真实错误统计描述，不能靠形容词证明。
