# 成功样本筛选与反思机制评测

## 这次补充改变了什么

项目作者于 2026-10-22 说明：历史“关闭反思”组通常保留一次轨迹，
“开启反思”组会重复采样，并在答对时保留最终成功轨迹。缺失的尝试和每题采样次数没有完整记录。

这说明旧分数同时受纠错、更多采样和按结果筛选影响。
原 43% 自定义分数、重新计算的 29.5% EM，都只描述留存记录，不能单独归因于反思。
改用严格判分也不能恢复已经缺失的失败尝试，因此不能从旧日志补算真实 pass@1/pass@k。

这不是说成功样本没有用途。用途需要区分：

| 用途 | 成功样本怎样使用 |
|---|---|
| SFT 数据 | 可筛选正确回答作为示范，记录生成与筛选方式 |
| 偏好数据 | 可比较同题正确/错误回答，但标签和上下文一致性需要核对 |
| Agent 决策训练 | 需要真实请求上下文、动作与观察，最终正确不保证中间步骤可信 |
| 反思效果评测 | 所有预定尝试都要进入分母，不能只保存答对的一次 |
| oracle coverage | 可报告若允许知道正确答案，多次尝试中至少一次成功的比例；不是线上选择准确率 |

例如，假设每次独立采样成功率均为 20%，抽 8 次至少成功一次的概率为
1-(1-0.2)^8，约 83.2%。这是数学示意，不能用于估计本项目真实概率。

## 已做的改造

1. data/source_provenance.json 按内容 SHA256 标记四份历史日志，记录作者披露的采集方式。
2. eval/rescore.py 保留可重算的记录级 EM/F1，另设无法恢复的单次/多次指标为 null。
3. posttrain/build_data.py 继续允许筛选训练示范，清楚标明用途和源记录选择方式。
4. 原训练用的 outputs/posttrain_answer、模型与原训练报告保持不变。
   新增来源说明的导出放在 outputs/posttrain_answer_v2，防止覆盖原实验的数据校验值。
5. reports/validation.json 对原 SFT/DPO 做回溯来源审计，不改写训练是否完成、损失或原模型。
6. eval/fair_compare.py 预先保存计划，逐条追加全部尝试，再统一评分。
7. 每次模型请求记录 effective_seed，不再依赖本地客户端累计调用次数改变种子。
8. fixture 演示数据被明确标记，禁止默认混入真实训练数据。

## 新固定预算对照

默认每题每个策略最多 8 次模型调用，最多 8 次工具调用：

| 策略 | 轨迹数 | 每条轨迹模型调用上限 | 可用反馈 |
|---|---:|---:|---|
| react_single | 1 | 8 | 普通工具观察，错误后结束 |
| react_error_feedback | 1 | 8 | 格式或工具错误反馈，允许修正 |
| react_restarts | 4 | 2 | 各自独立的普通 ReAct |

这是相同预算上限，不保证实际调用、输入 token 或耗时完全相同。
当前“反思”具体指格式/工具错误反馈，不是根据标准答案告诉模型哪里错了。
实际调用、token 和步数均另行报告；预算不整除重启次数时拒绝运行。

多次采样组：
- 固定生成全部 N 条，不会在首次答对后退出。
- 正常选择使用归一化答案的多数投票，平票取最早候选，完全不查看标准答案。
- selected_em/f1 是该选择规则实际得到的结果。
- oracle_any_success_rate 是“至少一次正确”的诊断上界，不冒充多数投票成绩。
- pass_at_k 从完整固定样本计算，适用可比的独立采样假设，不能用于旧的筛选记录。

## 怎样运行

不联网的固定响应协议演示：

    python -m eval.fair_compare --backend fixture

使用本地模型与合成工具环境：

    .\.venv-train\Scripts\python.exe -m eval.fair_compare --backend local --fixture-environment --total-calls 8 --restarts 4

这两种均标记 fixture_only，只验证实现，不作为正式模型效果证据。
本轮两种演示均已运行；本地 0.5B 仍有工具格式失败，未以此声称反思有效。

真实数据与线上 Wikipedia（有网络依赖，不调用外部 LLM API）：

    .\.venv-train\Scripts\python.exe -m eval.fair_compare --backend local --data data/hotpotqa200.jsonl --split test --max-samples 5 --total-calls 8 --restarts 4

外部模型 API 方式需自己的本地凭据，会真实计费：

    python -m eval.fair_compare --backend api --model Qwen/Qwen2.5-7B-Instruct --max-samples 5

输出目录内：
- plan.json：运行前锁定的问题、种子、预算、代码与数据版本。
- attempts.jsonl：逐条保存生成结果，错误和失败也保留，不在生成时使用标准答案。
- report.json：全部尝试及事后评分，包含实际选择结果与单独的 oracle 上界。

默认新建唯一目录，拒绝覆盖旧实验。中断留下的部分尝试不能当成完整结果。
真实反思增益仍需全量留痕的新对照；当前没有从历史数据得出这种增益。

## 对已完成本地实验的影响

20 步 SFT、5 步 DPO 的确实训事实不变。
训练材料现明确属于按结果筛选的规则示范，而不是未经筛选的采样分布。
后来的 10 题直接回答记录没有按答对与否保留：30%/20%/20% 仍是那次探索性切片的观察，
但数据小、测试池有历史接触，不能证明泛化提升，更不能证明反思机制的作用。

旧数学样本暂不导出，因为运行器插入了基于标准答案判断的合成结束响应。
将真实正确代码另行整理为带 oracle 标签的训练样本可以单独研究，不能冒充模型自然完成的轨迹。

## 简历中可以增加的一句

“针对重复采样与成功轨迹筛选造成的评测混杂，设计固定预算的 ReAct、
错误反馈和独立重采样对照，保存完整尝试，区分实际答案选择准确率与 oracle 覆盖率。”

这是已实现并验证的评测设计。没有新的效果证据时，不写“反思显著提升准确率”。
