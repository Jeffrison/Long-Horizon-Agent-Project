# 学习与实验路线

这是在你原有 ReAct Agent 上借助编码助手协作完善的项目。面试区分原有工作、
本次改造和自己能独立解释的部分，不必声称全部独立手写。

## 1. Agent 执行
先运行 python -m examples.offline_demo，查看生成的完整轨迹，再读 agent/react_loop.py。
应能解释：
- 模型输出如何变成工具调用，Observation 如何进入下次上下文？
- 为什么无效输出只进日志，不进历史？
- 为什么格式重试也要计入调用预算？
- 最近两轮窗口可能丢失什么信息？什么时候应换成证据摘要？
- 为什么不能用标准答案决定工具结果是否可以提前结束？

## 2. Eval
阅读 eval/metrics.py，运行旧日志重评分。
应能举例解释：
- “包含正确答案”不等于正确，yes/no 也不能靠 same、both 等词判断。
- EM 与 token F1 的不同；本项目只评最终答案，不评 supporting facts。
- 回答完成率、任务正确率、格式错误率分别用什么分母？
- 旧 8%→43% 包含不同重试开销，不能声称等成本提升。

## 3. 后训练数据
查看 outputs/posttrain_answer/manifest.json。
- 真实生成且严格 EM 通过的答案作为正例；有错误尝试的同题才构成偏好对。
- 规则标签是 silver labels，不是人工偏好；别名答案也可能被 EM 错拒。
- 答案级数据只监督最终回答，不训练工具选择。
- 新版决策数据使用真实请求上下文，completion 只含 assistant 的一次决策。
- DPO 两个回答必须共享前缀，不能把不同证据上下文硬配对。
- 按问题划分，而不是随机打散轨迹，否则同题可能进入训练和测试。

## 4. LoRA SFT / DPO
先检查 reports/validation.json，区分实际训练和干跑。
用项目 .venv-train，避免改动原全局环境。

SFT 要会讲：completion-only loss、LoRA rank/alpha、梯度累积、
梯度检查点、adapter 保存与权重合并。

DPO 要会讲：prompt/chosen/rejected、reference、beta。
如果接在 SFT 之后，reference 也应是 SFT checkpoint。
当前只有 15 对训练偏好且验证集为空，仅适合流程验证，不足以证明稳定提升。
本项目没有 PPO/GRPO 在线训练，不能称为已经完成 Agentic RL。

## 5. 下一轮有说服力的实验
1. 新增从未用于训练和调参的问题，确认数据使用条件。
2. 固定模型、提示词、预算、种子与证据来源。
3. 比较 direct、ReAct、ReAct+纠错，记录 EM/F1、调用、token、延迟。
4. 对基座、SFT、DPO 使用同一测试切片与解码设置。
5. 分析检索失败、工具失败、格式失败、证据不足和推理错误。
6. 如果无提升，也如实报告并分析数据规模、标签噪声与任务差异。

先亲自运行、修改并解释一遍，再把具体实现当作自己的熟练能力。
