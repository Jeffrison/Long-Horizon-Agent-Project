# 最终复测预声明：受控语料 + 限制 API 并发

前期原始/实时/并发运行全部保留；它们是本次开发与基础设施诊断的一部分，不能从中挑选最高准确率作为最终结果。

## 基础设施故障与修正

- 原实时计划：Wikipedia 429 与 API read timeout，26/1290 后停止，见 reports/live-interrupted-20261025。
- 固定语料压力运行：完成全部 1290 个计划项，但大批请求在首步即 HTTP 失败；旧客户端只保存了异常类型，不能追溯具体 HTTP 状态。完整原始记录见 reports/snapshot-api-stress-20261025。
- 两次明确不计分的单请求诊断（一次 max_tokens=1、一次原始上限）验证失败上下文在单独请求时可被 API 接收；诊断输出不用于任何准确率。
- 修正客户端：单进程最多 2 个在途请求，发送间隔至少 1 秒；429/5xx 触发后续请求的 30–60 秒冷却；当前失败仍计分，不重试该题。HTTP 状态显式落盘。
- 上述单独运行的 dev health 检查完成后，再启动最终实验；不同时启动多个 API rollout 进程绕过进程内限流。

## 主实验

- 原本冻结 test 的全部 215 题（QA 166 / MATH 49）。
- seed=11；每题 OFF/ON 各一条轨迹，共 **430 条**。
- 固定语料 snapshot，max_calls=8，max_tokens=600，temperature=0.1，history_turns=8。
- workers=4；HTTP in-flight cap=2；api_interval=1 秒。
- 所有错误计入分母，不因为答错而重跑。和压力运行属于不同、明确记录基础设施设置的实验，不把两轮合并取最佳答案。

## 稳定性补充实验

- 每个任务按问题哈希排序的前 10 道 test 题，共 20 题。
- 额外 seed=29、47；OFF/ON，共 **80 条**。
- 同一设置，主实验结束后单独运行。
- seed=11 使用主实验中相同题目的原有轨迹，绝不额外生成。三种子稳健性分析只使用这 20 道预定题，不能当作 215 道题的三种子结果。

## 判读原则

主实验给出严格 pass@1 / QA EM、F1；统计配对差异与不确定性。稳定性只说明小子集的种子变化。若基础设施仍发生错误，如实报告；不得把模型故障排除后伪称完整集准确率。若没有显著反思增益，应当写成消融发现而非提升。

这套设计是对前期基础设施诊断后的预声明，不是从始至终未接触数据的盲测。所有题目来自历史项目，局限始终保留。
